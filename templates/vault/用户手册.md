# Agent Memory Beacon — 用户手册 / User Manual

> 给你（人类用户）的完整使用指南。AI 助手另有 [[README|README]] 入口。
> Complete guide for you (the human user). AI assistants have their own [[README|README]] entry point.

---

## 一、这是什么？/ 1. What Is This?

一句话：**把所有 AI 助手的"记忆"集中到一个 Obsidian Vault 里，让它们互相学习、不再遗忘。**

你每和一个 AI 聊完天，它会写一份会话纪要存到这里。每周日，Python 脚本自动扫描所有纪要，发现跨项目的错误模式，生成规则提案。你只需点点审批——规则就会自动同步到项目配置，所有 AI 都能读到。

Bottom line: **Consolidate all AI assistants' "memory" into one Obsidian Vault so they learn from each other and never forget.**

After each AI chat session, a summary is written here. Every Sunday, Python scripts auto-scan all summaries, discover cross-project error patterns, and generate rule proposals. You just click to approve — rules auto-sync to project configs for all AIs to read.

## 二、快速开始 / 2. Quick Start

### 2.1 初始化 / Initialize

```bash
SOURCE="/absolute/path/to/agent-memory-beacon"
cd "$SOURCE/scripts"
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/python setup.py
.venv/bin/python install_runtime.py --verify-release
.venv/bin/python install_runtime.py
```

脚本会问你 / The script will ask:
1. **Vault 路径 / Vault path** — 新安装默认 `~/AgentMemoryBeacon/`；existing `~/ObsidianBrain` 会继续使用配置路径，不会移动目录。
2. **项目根目录 / Project root** — 你的代码项目根在哪？（里面有 CLAUDE.md 的那个目录）
3. **项目列表 / Project list** — 你要跟踪哪些项目？用逗号分隔，如 `web-app, data-pipeline`

初始化后你会得到 / After init you get:
- 完整的 vault 目录结构 / Full vault directory structure
- 所有模板文件 / All template files
- `config.yaml` 配置文件 / Config file
- Codex、Claude 和 ZCode 集成安装器 / Codex, Claude, and ZCode installers

### 2.2 配置 CLAUDE.md / Configure CLAUDE.md

推荐运行 `scripts/install_claude.py`；手动配置时，把
`patches/AGENT_MEMORY_BEACON.md.patch` 的内容粘贴到 `CLAUDE.md`。它添加了三段标记块：

```
<!-- COMPILED:RULES_START -->  ← compiler 自动填充规则
<!-- COMPILED:RULES_END -->

<!-- COMPILED:PROJECTS_START --> ← compiler 自动填充项目信息
<!-- COMPILED:PROJECTS_END -->

### Session Annotation Rules  ← 告诉 AI 怎么写 [DECISION]/[ERROR]/[SESSION_SUMMARY]
```

**不要手动编辑 COMPILED 块**——它们是 `compiler.py` 自动维护的。你在 vault 里审批完规则，周日脚本自动同步到这里。

**Do NOT manually edit COMPILED blocks** — they are auto-maintained by `compiler.py`. When you approve rules in the vault, Sunday's script auto-syncs them here.

### 2.3 第一次跑 / First Run

```bash
RUNTIME="$HOME/.local/share/agent-memory-beacon/runtime"
"$RUNTIME/.venv/bin/python" "$RUNTIME/scripts/runner.py" --dry-run
"$RUNTIME/.venv/bin/python" "$RUNTIME/scripts/runner.py"
```

### 2.4 配置定时任务 / Schedule Weekly Run

当前 canonical authority 正式运行在 macOS。`install_runtime.py` 会按配置安装并加载 harvest、weekly，以及启用 authority sync 时的 sync LaunchAgent；无需另配 cron 或常驻 Python 进程。验证：

```bash
launchctl print "gui/$(id -u)/io.agent-memory-beacon.harvest"
launchctl print "gui/$(id -u)/io.agent-memory-beacon.weekly"
# 仅在 beacon_sync authority 已启用时存在
launchctl print "gui/$(id -u)/io.agent-memory-beacon.sync"
```

## 四、日常工作流 / 4. Daily Workflow

### 4.1 你和 AI 聊天时 / During Chat

你什么都不用做。AI 会自动：
- 在关键决策后写 `[DECISION: ...]`
- 遇到错误后写 `[ERROR: ...]`
- 用户提出可迁移的新颖思路时写 `[LEARN: ...]`；完整的一次性启发可直接成为 seed
- 会话结束时写 `[SESSION_SUMMARY]`
- Codex 长对话在第 5 条实质消息后开始静默滚动摘要，之后按消息数或 30 分钟间隔覆盖同一份 session 摘要

LEARN 的候选在 `04-Feedback/_insight-candidates/`，正式记录在 `05-Agent-Memory/insights.md`。未来只有设计、比较、类比、替代方案或卡住求解等探索任务会自动读取，最多两条；Insight 不能覆盖你的当前指令或正式 Decision/Workflow/Error。召回结果会显示稳定 `id`；只有看到准确 ID 且关系明确时，AI 才能在 LEARN 中追加 `supports`、`operationalized_as` 或 `related_to`，不能猜测或为了连线而填写。

滚动摘要复用当前 Codex 回答，不会额外调用一个模型。它只保存当前目标、主题、进展、约束和待办，不复制完整 transcript；后续相关任务最多读取一条 `[CONTEXT]`。`CONTEXT` 只是低优先级会话证据，不是正式事实或指令，也不会进入 lifecycle、图谱扩展或 AGENTS 编译。

### 4.2 周日 / Sunday

脚本自动跑，你会得到：
- 一份**周报**（`04-Feedback/weekly-reports/{YYYY}-W{ww}.md`）
- 如果有跨项目模式（3+ 项目出现同一错误）→ 自动生成**审批卡**（`00-Rules/_inbox/` 里）

### 4.3 下次开 Claude / Next Chat Session

Claude 会话开始时，如果 `_inbox/` 里有待审批规则，AI 会提醒你：
```
⏳ 1 rule pending approval:
📌 redis_connection_timeout across 3 projects (5 occurrences)
[Y] 批准/Approve  [N] 拒绝/Reject  [M] 修改/Modify  [S] 跳过/Skip
```

### 4.4 审批流程 / Approval Flow

```
AI 提案 / AI proposes
  │
  ├─ [Y] 批准/Approve → 规则进入 beta（30天后自动转正）/ Rule enters beta (auto-promoted after 30 days)
  ├─ [N] 拒绝/Reject → 移到 _rejected/（30天后自动清理）/ Moved to _rejected/ (auto-cleaned after 30 days)
  ├─ [M] 修改/Modify → AI 按你的要求修改后重新提案 / AI revises and resubmits
  └─ [S] 跳过/Skip → 直到第 N 次触发再提醒 / Remind after N more triggers (see skip_until)
```

## 五、阅读周报 / 5. Reading Weekly Reports

周报在 `04-Feedback/weekly-reports/{YYYY}-W{ww}.md`。每周日自动生成。

周报包含 / Each report contains:
- **扫描统计 / Scan stats** — 扫了多少 session、花了多久
- **新增模式 / New patterns** — 这周发现了哪些新错误模式
- **规则审批 / Rule approvals** — 这周审批/归档了哪些规则
- **跨项目热点 / Cross-project hotspots** — 哪些错误跨了多个项目
- **元健康 / Meta health** — 扫描器本身有没有出问题

**看周报的最佳时机**：周日晚或周一早上，花 2 分钟过一遍。

## 六、手动触发扫描 / 6. Manual Scan Trigger

### 查看效果与转化建议

- `04-Feedback/memory-effectiveness.md`：查看每个精确记忆 revision 的召回次数、弱接受、纠正和人工 helpful/misleading 信号。
- `04-Feedback/_promotion-proposals/`：查看是否建议把稳定 Decision、Error 或 Workflow 转成测试、runbook 或受管规则。这里的文件只是候选，不会自动执行。
- Codex 动态记忆行中的 `why_recalled`：说明是内容、类型、时间、图谱还是同一任务经验链命中。
- 同一行的 `authority`：说明该记忆的权威角色及规范/执行路径；`unspecified` 表示尚未声明权威合同。

需要手动刷新时运行 weekly maintain step；预览不会写文件：

```bash
"$RUNTIME/.venv/bin/python" "$RUNTIME/scripts/runner.py" --step maintain --dry-run
"$RUNTIME/.venv/bin/python" "$RUNTIME/scripts/runner.py" --step maintain
```


## 八、添加自定义错误分类 / 8. Adding Error Categories

编辑 `04-Feedback/error-taxonomy.md` 的 YAML frontmatter。模板里已经有一套通用分类：

```yaml
categories:
  - name: "R-plotting"
    # ...
  - name: "python-encoding"
    # ...
```

你可以：
- **删除**不需要的分类
- **添加**项目专属的分类（如 `k8s-deploy`、`sql-optimize`）
- **修改**子分类和正则匹配规则

分类的名字不重要（不会自动用于匹配），重要的是 `keywords` 字段——脚本用这些关键词从 session 里筛选候选。

## 九、跨设备同步 / 9. Cross-Device Sync

Windows 也可以自动采集 Codex/Claude 对话，但正式 Vault 仍只由 Mac 写入。
Windows 发送不可变 transcript evidence，Mac 使用同一套记忆质量门处理，再发布
经过 SHA-256 校验的只读副本。

协议版本不是一个全局数字：transcript/gap event + ready 保持 v1，attachment
event + ready 使用 v2，Producer state 为 v3，Mac ledger 为 v4。新附件只从
`attachment_roots` 内的 transcript 明确引用采集，落到：

```text
Attachments/Agent-Memory-Beacon/remote/objects/<sha[:2]>/<sha>.<ext>
04-Feedback/remote-attachments/<device>/<producer>/<seq20>-<event-id>.md
```

receipt 必须证明 blob 和 metadata 的路径、哈希、大小都属于同一 sealed
generation；只有写进 Vault、却没有进入 generation manifest，不算完成。

Syncthing 只同步两个传输目录：

| Folder | Windows | Mac |
|---|---|---|
| `amb-windows-outbox` | `%USERPROFILE%\AgentMemoryBeaconSync\outbox`，Send Only | `~/AgentMemoryBeaconSync/inbox/windows-main`，Receive Only |
| `amb-mac-published` | `%USERPROFILE%\AgentMemoryBeaconSync\published`，Receive Only | `~/AgentMemoryBeaconSync/published`，Send Only |

不要同步 Mac canonical Vault、Windows replica、state 或 attachment roots，也不要
直接编辑 replica。程序不会替你配置 Syncthing/Tailscale；它只生成、验证、归并
和物化两个传输目录中的数据。

Windows 最低支持 Windows 10 1809 / Windows Server 2019（build 17763），
Python 最低版本为 3.11。配置中的 state、outbox、inbox、published、
received-published、replica、attachment roots 和 canonical Vault 必须是互不包含
的绝对路径，也不能用符号链接或大小写别名把它们指回彼此。

Mac 配置好 authority 和 Syncthing 后，在源码根目录执行：

```bash
cd /absolute/path/to/agent-memory-beacon
PY="$PWD/scripts/.venv/bin/python"
CFG="$PWD/scripts/config.yaml"
"$PY" -B scripts/beacon_sync.py --config "$CFG" doctor
"$PY" -B scripts/install_runtime.py --verify-release
"$PY" -B scripts/install_runtime.py --dry-run
"$PY" -B scripts/install_runtime.py

RUNTIME="$HOME/.local/share/agent-memory-beacon/runtime"
"$RUNTIME/.venv/bin/python" -B "$RUNTIME/scripts/beacon_sync.py" \
  --config "$RUNTIME/scripts/config.yaml" run
"$RUNTIME/.venv/bin/python" -B "$RUNTIME/scripts/doctor.py" --profile live
```

authority sync 会作为 stable runtime 事务中的可选 LaunchAgent 安装。Hook、context
和所有已配置 LaunchAgent 由 manifest 动态枚举和回滚，不依赖固定文件数量。

Windows 首次启用先在 PowerShell 的源码根目录固化 identity，并建立 baseline：

```powershell
Set-Location C:\absolute\path\to\agent-memory-beacon
py -3.11 -m venv .\scripts\.venv
$Python = (Resolve-Path .\scripts\.venv\Scripts\python.exe).Path
$Config = (Resolve-Path .\scripts\config.yaml).Path
& $Python -m pip install --requirement .\scripts\requirements.lock
& $Python -m pip check
& $Python -B .\scripts\beacon_sync.py --config $Config init
& $Python -B .\scripts\beacon_sync.py --config $Config collect
```

普通 `collect` 不上传启用前历史。只有明确需要历史导入时，用这条替代首次
`collect`：

```powershell
& $Python -B .\scripts\beacon_sync.py --config $Config collect --include-existing
```

Mac 收到 outbox 并发布第一代以后，先等 `received-published` 完整到达 Windows，
再在预期的空 replica 上人工执行一次 bootstrap。只有 bootstrap 和 Doctor 都
通过后，才安装 Windows Task Scheduler 作业：

```powershell
& $Python -B .\scripts\beacon_sync.py --config $Config materialize --bootstrap
& $Python -B .\scripts\beacon_sync.py --config $Config doctor

$RuntimeRoot = "$env:LOCALAPPDATA\AgentMemoryBeacon\runtime"
& $Python -B .\scripts\install_beacon_sync.py --config $Config --runtime-root $RuntimeRoot --codex-hooks --claude-hooks --dry-run
$Installed = (& $Python -B .\scripts\install_beacon_sync.py --config $Config --runtime-root $RuntimeRoot --codex-hooks --claude-hooks | ConvertFrom-Json)
```

不用 Claude 时省略 `--claude-hooks`，不用 Codex 时省略 `--codex-hooks`。安装器会
先创建并验证
`%LOCALAPPDATA%\AgentMemoryBeacon\runtime\releases\<release-id>`，运行同步测试、
`pip check`、producer init、quick Doctor 和 manifest 验证，再让当前用户 Task/hook
指向 release 内 Python、脚本和配置。正式 Task 不指向 Git checkout 或系统
Python；旧 release 保留，不自动清理。

用安装结果中的真实绑定运行 stable Doctor：

```powershell
$Binding = $Installed.actions[0].runtime
$RuntimePython = [string]$Binding.python_path
$RuntimeScript = [string]$Binding.script_path
$RuntimeConfig = [string]$Binding.config_path
$RuntimeDoctor = Join-Path (Split-Path $RuntimeScript) "doctor.py"
& $RuntimePython -B $RuntimeScript --config $RuntimeConfig doctor
& $RuntimePython -B $RuntimeDoctor --profile live
```

后台 `run` 不会隐式 bootstrap，也不会接管非空或未知副本。首次物化成功后，
Windows Task 才按 collect、逐代 materialize、receipt GC 自动推进。卸载只移除
带 ownership 标记的 Task 和所选 hook，不删除 outbox、state、release 或 replica：

```powershell
& $Python -B .\scripts\install_beacon_sync.py --config $Config --uninstall --codex-hooks --claude-hooks
```

常见停机状态必须保留现场并从根因恢复：

- `missing object`：让 Syncthing 补齐同一 bundle 或 generation，保留 ready/current。
- `sequence gap`：恢复缺失的较低 sequence，不能跳到更高 sequence。
- attachment receipt 未绑定：保留 inbox，在 Mac 重跑 `run`，让 reducer 重建缺失
  effect，并确认 blob + metadata 同时进入 generation。
- `parent mismatch`：先同步并应用缺失的中间 generation。
- `replica drift`：另存本地修改，从已验证 active generation 或备份恢复原字节。
- `bootstrap required`：只在确认 replica 是预期空目录后显式 bootstrap。
- `partial generation binding`：停止发布，从完整备份恢复 ledger 或人工审计。
- Task/hook 漂移：先运行安装器 `--dry-run`，再幂等重装；无 ownership 的同名
  Task 不能强制覆盖。

不要删除 ledger、伪造 receipt/current/active marker、跳过 generation，或关闭
路径和哈希检查来强行继续。远端设备无权执行正式记忆的撤回、替代、过期或恢复。

## 十、常见问题 / 10. FAQ

### Q: 会不会很占空间？
A: 全是 Markdown 文本文件。100 个 session 纪要大约 500 KB。JSONL 备份略大但会定期清理。完全不用担心。

### Q: 我同时用多个 AI 工具（Claude、GPT、Gemini）能行吗？
A: 行。只要它们都能读写 Markdown 文件，就都能参与这个系统。关键是一致遵守 `[DECISION]`/`[ERROR]`/`[SESSION_SUMMARY]` 的格式约定。

### Q: 我不懂 Python 能跑起来吗？
A: `setup.py` 会引导你。源码和稳定运行时要求 Python 3.11+；依赖统一从 `requirements.lock` 安装，`install_runtime.py` 会创建隔离的运行时 venv。后台任务由 macOS launchd 安装器维护。

### Q: 规则审批会不会烦死我？
A: 不会。审批卡只在两个条件下触发：(1) 同一个错误模式出现在 3+ 个项目中；(2) 你之前没有拒绝过类似的。而且你可以点 `S` 跳过——"再出现 N 次再提醒"。

### Q: AI 写的规则不靠谱怎么办？
A: 这是双向审批的意义——AI 提案、你决策。AI 不会自动应用任何规则。所有规则都要你点 Y 才生效。

### Q: 我的 vault 能放 GitHub 吗？
A: 可以。建议先加 `.gitignore` 排除 `04-Feedback/_logs/`、`_attachments/` 里的大文件。配置文件里如果有 API key 记得放 `.env` 而不要提交。

### Q: LLM 聚类要钱吗？
A: 可选功能。不配 API key 也能跑（用关键词模式）。配了 API key 后语义聚类更准，但因为有本地预筛选，每轮调用量很小（几 KB token），费用极低。
